# Wendy

학교 친구들과 일정을 함께 보는 그룹 캘린더 웹앱입니다.
개인 일정과 그룹 일정을 한 달력에서 관리하고, NEIS에서 받아온 우리 학교(그룹 화면에서는 그룹원들 학교)의 학사일정과 공휴일을 자동으로 표시합니다.
그룹원이 일정을 바꾸면 실시간으로, 학사일정이 바뀌면 다음 확인 때 알림으로 알려줍니다.

- 배포 주소: https://gimgibum.github.io/Wendy/
- 저장소: https://github.com/gimgibum/Wendy

## 주요 기능

- 아이디 + 비밀번호 회원가입 / 로그인 (Supabase Auth)
- 온보딩에서 내 학교 검색·등록 (NEIS). 건너뛸 수 있고, 메뉴 "내 학교 변경"에서 나중에 바꿀 수 있음
- 개인 캘린더: 일정 추가 / 수정 / 삭제, 일정 색상
- 그룹 캘린더: 그룹 생성 → 6자리 초대 코드 → 참여(닉네임·색상). 멤버별 색상으로 일정 구분, 닉네임·색상 변경
- 그룹장: 그룹 이름 변경, 멤버 내보내기, 그룹 삭제, 초대 코드 복사
- 학사일정: 개인 화면은 내 학교, 그룹 화면은 그룹원들 학교의 학사일정(시험, 방학 등) 표시
- 공휴일 표시 (한국천문연구원 특일 정보 API. 키가 없거나 아직 발표 전인 연도는 규칙으로 계산)
- 알림
  - 그룹원이 바꾼 일정: 앱을 켜둔 동안은 실시간, 꺼둔 사이의 변경은 다음 접속 때 한 번에
  - 내 학교 학사일정 변경: 접속할 때, 30분마다, 다른 탭에 있다가 돌아왔을 때 확인
  - 화면 위 배너로 표시하고, 메뉴에서 켜두면 다른 탭을 보고 있을 때 브라우저 알림으로도 표시

## 테스트 계정 가이드

### 계정 규칙

- 아이디: 영문·숫자·`.` `_` `-` 조합 **3~20자** (대소문자는 구분하지 않음)
- 비밀번호: **6자 이상**
- 회원가입이 끝나면 로그인 화면으로 돌아오므로 직접 로그인합니다. 첫 로그인은 온보딩(학교 등록)을 거쳐 캘린더로 갑니다.
- 계정은 팀 공용 Supabase에 저장되므로, 누가 만들었든 모든 팀원이 같은 계정으로 로그인할 수 있습니다.

### 테스트 계정 만들기

1. https://gimgibum.github.io/Wendy/ → **회원가입** → 아이디·비밀번호 입력 → "회원가입이 완료됐어요" → 로그인
2. 온보딩에서 학교 이름 일부를 검색(예: `서울고`) → 학교 선택 → **다음**
   (건너뛰기를 누르면 학사일정 없이 시작하고, 나중에 메뉴 "내 학교 변경"에서 등록할 수 있습니다)
3. 두 번째 계정은 **시크릿 창**이나 다른 브라우저에서 같은 방법으로 만듭니다 (아래 주의 참고)

### 두 계정으로 테스트할 때 주의

같은 브라우저의 모든 탭은 **로그인 세션을 공유**합니다. 한 탭에서 다른 계정으로 로그인하면 열려 있던 다른 탭도 그 계정으로 바뀝니다.
두 번째 계정은 반드시 **시크릿 창, 다른 브라우저, 또는 다른 브라우저 프로필**에서 로그인하세요.

### 시연 시나리오

아래에서 **A**는 그룹장 계정, **B**는 그룹원 계정입니다.

1. **개인 일정** (계정 하나로 가능)
   날짜를 클릭해 일정을 추가하고 수정·삭제해 봅니다. 등록한 학교의 학사일정과 공휴일이 달력에 표시되는지 확인합니다.
2. **그룹 만들기 / 참여**
   - A: 메뉴(☰) → **+ 그룹 추가 (생성/참여)** → **그룹 만들기** 탭 → 그룹 이름·닉네임·내 색상 입력 → 생성.
     초대 코드가 안내창에 뜨고, 메뉴 **이 그룹 관리 (초대 코드·멤버)** 에서 다시 복사할 수 있습니다.
   - B(시크릿 창): 같은 메뉴 → **그룹 참여하기** 탭 → 초대 코드·닉네임·색상 입력 → 참여.
     A가 쓰는 색은 고를 수 없습니다 (한 그룹 안에서 색이 겹치면 누구 일정인지 구분이 안 되므로).
3. **그룹 일정 실시간 알림**
   A는 그 그룹 캘린더를 열어 둡니다. B가 일정을 추가·수정·삭제하면 약 1.5초 뒤 A 화면 위에
   "○○ 일정이 변경됐어요 (n건)" 배너가 뜨고 달력에도 반영됩니다.
   - 내가 바꾼 일정은 나에게 알리지 않습니다. (다른 기기에서 내가 바꾼 것도 달력에는 반영됨)
   - 여러 날짜에 한꺼번에 일정을 등록하면 알림 하나로 묶입니다.
4. **브라우저 알림**
   A: 메뉴 → **일정 변경 알림 받기** → 브라우저 권한 **허용** → 다른 탭으로 이동.
   B가 일정을 바꾸면 운영체제 알림이 뜹니다. (A가 Wendy 탭을 보고 있는 동안에는 배너만 뜹니다)
5. **앱을 꺼둔 사이의 변경**
   A: 창을 닫거나 로그아웃 → B: 일정 변경 → A: 다시 로그인 → 접속 직후 그 사이에 바뀐 일정이 한 번에 알림으로 뜹니다.
6. **학사일정 변경 알림** (NEIS 데이터가 실제로 바뀌어야 해서 바로 재현하기 어려움)
   개발자 도구 → Application → Local Storage → `wendy:schoolSnapshot:<내 userId>:<교육청코드>:<학교코드>` 값을 열어
   `events` 안의 날짜 하나를 지우고 저장한 뒤 새로고침하면, 그 날짜의 일정이 "추가"로 잡혀
   "○○ 학사일정이 변경됐어요" 배너가 뜹니다. (그룹 일정도 `wendy:groupSnapshot:<내 userId>`로 같은 원리)
7. **정리**
   테스트가 끝나면 A가 그룹 관리 화면에서 그룹을 삭제합니다. 테스트 계정 자체를 지우려면 Supabase 대시보드 → Authentication → Users에서 삭제합니다.

## 자주 겪는 문제

| 증상 | 원인 / 해결 |
| --- | --- |
| 화면이 비어 있고 콘솔에 CORS 또는 module 오류 | HTML을 `file://`로 열었음 → 로컬 서버로 열기 (실행 방법 3번) |
| 그룹 참여 시 "DB에 그룹 참여 함수가 아직 없어요" | `supabase/join_group.sql` 미실행 |
| 그룹원이 바꾼 일정 알림이 안 오고 콘솔에 "그룹 일정 실시간 연결에 실패했어요" | `supabase/realtime.sql` 미실행 또는 Realtime 꺼짐. 실시간을 못 받아도 다음 접속 때 스냅샷 비교로 따라잡음 |
| 새 아이디인데 "이미 사용 중인 아이디예요" | Supabase Auth의 "Confirm email"이 켜져 있음 (Supabase 설정 1번) |
| 브라우저 알림이 안 뜸 | 메뉴에서 알림을 켰는지, 권한을 허용했는지, **다른 탭을 보고 있는 상태**인지 확인. 차단했다면 주소창 왼쪽 사이트 설정에서 허용 |
| 학사일정이 안 보임 | 온보딩을 건너뛰었으면 메뉴 "내 학교 변경"에서 등록. 콘솔에 "학사일정 요청이 실패했습니다"가 있으면 NEIS 키 또는 요청 한도 문제 |
